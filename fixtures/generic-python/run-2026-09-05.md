## Findings, in order of severity

1. **No handoff template.** `templates/expected-files.md` and the `handoff_docs` convention require `docs/handoff-items/handoff-next-phase.md`, but `templates/docs/` has no template for it. The run improvised one: date, phase finished, where things stand, what to do next, suggested skills, pointing at the runbook. Fix: add `templates/docs/handoff-next-phase.md` in that shape.
2. **Compose file name collision.** The build writes `docker-compose.yml` for a Docker dev database. The generic deploy template for "Docker on a server I control" also needs a compose file, for the server. A project with both would have two files fighting for one name. This fixture avoided it only because the dev database is on localhost. Fix: the deploy templates name the server file `docker-compose.prod.yml`, and say so.
3. **Uncovered definition-of-done items and exports.** The intake's 7.2 export (CSV for the accountant) and its third done item (the accountant received a CSV) belong to no must-have story. The run attached the export to Task 05 and said so. Neither `SKILL.md` nor the templates say what to do with work that only 7.2 or Section 14 mentions. Fix: build step 3 says to attach such work to the closest slice, or add a slice, and to add the story to the PRD marked "(inferred)".
4. **Generic CI has no language setup step.** `reference/ci.md` gives checkout, install, test. Python needs `actions/setup-python`, Go needs `actions/setup-go`, and so on. The run added setup-python by itself. Fix: `ci.md` says the generic set adds the language's setup action before Install, names the common ones, and marks it "confirm".
5. **Connection-string scheme for the data layer.** `reference/dev-database.md` renders `postgresql://`. SQLAlchemy with psycopg 3 wants `postgresql+psycopg://`. The run noted it in Task 01 and `.env.example`. Fix: the generic skeleton's database step says to confirm the scheme the data layer expects; a Python first-class set would render it directly.
6. **Integrations section with 7.1 blank and 7.2 answered.** The PRD template says "omit when blank" for the section as a whole; with only the export answered, the run kept the heading and dropped the table. Fix: the template says the table renders only when 7.1 has entries.
