## Findings, in order of severity

1. **Runbook pushes before the secrets scan.** `reference/hosts.md` puts `git push -u origin` inside the create-repo block (step 0.1), but the secrets gate is step 0.4. Following the runbook as written pushes unscanned. Fix: remove the push line from every block in `hosts.md`; step 0.6 holds the single push line, after the gate.
2. **pnpm one-off commands render wrong.** `templates/tasks/ts-prisma-postgres/01-walking-skeleton.md` maps `{{pm exec}}` to `pnpm`, so `{{pm exec}} create-next-app@latest .` renders as `pnpm create-next-app@latest .`, which does not exist. One-off packages need `pnpm dlx` / `npx` / `yarn dlx` / `bunx`; installed bins need `pnpm prisma` / `npx prisma` / `yarn prisma` / `bunx prisma`. Same for `auth secret` and `vercel link`. Fix: split into `{{pm dlx}}` and `{{pm bin}}` in the skeleton, sign-in, and deploy templates, and use `pnpm create next-app@latest` for the initializer.
3. **Skills list is never trimmed in build-from-file mode.** `SKILL.md` section 6 shows the detected list "once during the walkthrough". A complete intake skips the walkthrough, so the user never sees or trims it. Fix: show the list in the confirm step when no walkthrough ran.
4. **No `.gitignore` template.** `expected-files.md` lists `.gitignore` as a build output and `SKILL.md` says every generated file carries the header, but there is no template, so the run improvised one without a header. Fix: add `templates/docs/gitignore` with the header, `.env` rules, and stack-aware ignores (`node_modules/`, `.next/` for the TypeScript set).
5. **Env var names disagree between templates.** `templates/docs/env.example` says `{{PROVIDER}}_CLIENT_ID`; the ts sign-in template uses Auth.js, which reads `AUTH_<PROVIDER>_ID`, `AUTH_<PROVIDER>_SECRET`, and `AUTH_RESEND_KEY`. The run used the Auth.js names. Fix: env.example says which naming each template set uses.
6. **`PORT` in `.env.example` for Next.js.** Next reads `PORT` from the process environment, not from `.env`, so the line is misleading for the Next.js path. Fix: render `PORT` only for Express.
7. **Skeleton with a path that needs a signed-in user.** "A member votes" needs an identity before the sign-in task exists. The run invented a placeholder member key that Task 02 replaces. Neither skeleton template says to do this. Fix: one sentence in both skeletons: when the path needs a signed-in user, use a fixed placeholder identity and name the sign-in task as the one that replaces it.
8. **Playwright is not covered by `reference/ci.md`.** The run added `pnpm playwright install --with-deps` to the first slice's CI note by itself. Fix: `ci.md` gets a Playwright paragraph for when it is in `stack.tests`.
9. **Expected file names over-specify slugs.** The list names `04-vote-for-books.md`; another agent could reasonably write `04-vote.md`. Fix: the fixture lists say "one task file per must-have, slug may vary" and the check counts task files instead of matching names, except for the fixed ones (skeleton, sign-in, deploy, definition of done).
10. **Git identity.** The commit needs `user.name` and `user.email`. On a fresh machine it fails. Fix: `SKILL.md` step 5 says what to do when git has no identity: tell the user the two config commands and skip the commit.
11. **ECC detection is narrow.** `SKILL.md` looks for `~/.claude/commands/project-init.md`. ECC installed as a plugin lives under `~/.claude/plugins/cache/`. Fix: also look for a `project-init` command under the plugin cache.
